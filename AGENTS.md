# AGENTS.md

macOS dotfiles: `./dotfiles <module>` sets up this Mac from the repo. The
README covers the modules, the day-to-day recipes, and the **Development**
commands (tests, lint, secrets scan); read it before changing anything.

This file is the instructions file for every agent. Claude Code reads it only
while the repo has no `CLAUDE.md`, so add new rules here.

## This repo is live on this Mac

- Everything in `links.txt` is symlinked from `home/` into `~`, so editing
  `home/.zshrc` edits the shell config the person is using right now.
- Run `--dry-run`, `doctor` and `bats tests/` freely. Ask before any real run
  of `install`, `all`, `macos`, `iterm` or `update`: they change the Mac
  itself, and Homebrew adopting an already-installed app quits it while it's
  running (1Password etc.).
- `~/.claude/settings.json` is generated by `./dotfiles link` from
  `home/.claude/settings.json` plus the private, untracked
  `~/.claude/settings.private.json`. Change the repo file, then re-run `link`.
- `codex/config.toml` is a reference copy; the Codex app owns the live file.

## Writing scripts

- Target macOS's `/bin/bash` 3.2 (no associative arrays, no `${x,,}`).
- Every side effect goes through `run_cmd` from `lib/common.sh`, which is
  what makes `--dry-run` work. Report anything left undone with `skip`, so one
  failure never stops the rest.
- A module is `modules/<name>.sh` defining `<name>_help` and `<name>_main`,
  plus `tests/<name>.bats`, `docs/<name>.md` (including how to undo it), a
  line in the dispatcher's usage text and a row in the README modules table.

## Tests

- Tests run in a sandboxed `$HOME` with system commands replaced by
  `tests/stubs` (see `tests/helpers.bash`). Stub a new command by symlinking
  it to `_stub`.
- End `[[ … ]]` and `! cmd` checks with `|| false`; bash 3.2 ignores a
  failure in the middle of a test otherwise.
- The README tools table is generated: add tools to the `Brewfile` or the
  mise config with a `# Category | what it's for` comment, then run
  `bash lib/tools-table.sh --write`. A test fails while the table is stale.

## Public repo hygiene

- Write paths as `~`, never `/Users/<name>`; names, emails, hosts and IPs
  belong in the `*.local` / `settings.private.json` files. Tests check this,
  and a gitleaks pre-commit hook blocks secrets.
- `home/.config/nvim/lazy-lock.json` is tracked on purpose (pins plugins).

## Conventions

- British English in docs and messages. Docs are plain, second-person and
  written for someone who isn't a shell expert.
- Conventional commits with a scope: `feat(iterm): …`, `fix: …`.
- `docs/superpowers/` holds the original design and plan, kept as history;
  the code and README are the current truth.
- For tool reviews or version bumps, use the repo skills `tool-scout` and
  `dependency-updater` in `.claude/skills/`.
